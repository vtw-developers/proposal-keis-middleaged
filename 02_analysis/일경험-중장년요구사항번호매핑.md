# 일경험-중장년 요구사항 번호 매핑표

## 1. 매핑 기준

일경험 제안서를 참고하여 중장년내일센터 제안서를 작성할 때 요구사항 번호를 다음 기준으로 치환한다.

| 구분        | 적용 기준                                     |
| --------- | ----------------------------------------- |
| 동일 재사용    | 요구사항 번호와 명칭이 동일하거나, 실질 내용이 동일한 경우         |
| 번호 치환     | 내용은 유사하나 중장년 RFP에서 요구사항 번호가 변경된 경우        |
| 전면 재작성    | 청년 일경험 고유 기능으로, 중장년 업무 요구사항으로 대체해야 하는 경우  |
| 중장년 신규 반영 | 일경험 RFP에는 없거나 약한 내용이나, 중장년 RFP에 추가·확장된 경우 |

## 11. 제안서 작성 시 적용 원칙

### 11.1 그대로 가져와도 되는 영역

다음 영역은 일경험 제안서의 구조를 재사용하고, 문구만 중장년 사업 기준으로 수정한다.

* 성능 요구사항
* 인터페이스 요구사항
* 테스트 요구사항
* 품질 요구사항
* 유지보수 수행 요구사항
* 일부 보안 요구사항
* 일부 제약사항
* 일부 프로젝트관리 및 프로젝트지원 요구사항

### 11.2 반드시 중장년 기준으로 바꿔야 하는 영역

다음 영역은 일경험 내용을 그대로 쓰면 안 된다.

* 기능 요구사항
* 데이터 요구사항 번호
* 보안 요구사항 SER-006 이후 번호
* 프로젝트관리 요구사항 번호
* 프로젝트지원 요구사항 PSR-002 이후 번호
* 시스템장비구성 요구사항
* 아키텍처 요구사항
* 컨설팅 요구사항

### 11.3 기능 장표 작성 원칙

기능 장표는 일경험 SFR을 기준으로 하지 않고, 중장년 SFR-001~SFR-015를 기준으로 작성한다.

## 12. 최종 활용 요약

일경험 제안서를 중장년 제안서로 전환할 때는 다음처럼 처리한다.

| 영역      | 처리 방식                                         |
| ------- | --------------------------------------------- |
| 기능      | 중장년 SFR-001~015 기준으로 전면 재작성                   |
| 유지보수    | MAR-001 유지, 대상 시스템명만 중장년으로 변경                 |
| 성능      | PER-001~011 그대로 활용                            |
| 인터페이스   | SIR-001~007 그대로 활용                            |
| 데이터     | DAR 번호 치환 후 중장년 데이터 이관·정제·품질관리 내용 보강          |
| 테스트     | TER-001~010 그대로 활용                            |
| 보안      | SER-001~005는 유지, SER-006 이후는 중장년 기준으로 재배치     |
| 품질      | QUR-001~009 그대로 활용                            |
| 제약      | COR-001~007, COR-009는 유지, 나머지는 중장년 COR 기준 재배치 |
| 프로젝트관리  | PMR 번호 치환 및 중장년 신규 관리항목 반영                    |
| 프로젝트지원  | PSR-002 추가에 따른 번호 치환                          |
| CNR/ACR | 중장년에는 직접 매핑하지 않음                              |
| ECR     | 일경험 소프트웨어 구성 → 중장년 EDMS 이관 및 PaaS 구성 지원으로 재작성 |
