# 데이터 요구사항 (DAR)

### DAR-001 데이터 표준 수립 및 상위표준 준수

- 데이터 표준 수립 및 상위표준 준수
  - 시스템 구축에 필요한 데이터 표준항목(단어, 용어, 도메인, 코드)을 정의하여 구축되는 시스템의 데이터 표준 사전을 제정하여야 함
  - DB 표준항목 제정 시 범정부 표준(공공기관의 데이터베이스 표준화 지침(행정안전부 고시), 공통표준용어)과 발주기관 또는 국내·외 산업 표준을 준수하고 표준 사전에 준수 여부를 식별할 수 있도록 하여야 함
- 데이터 표준관리 방안
  - 발주기관의 표준도메인을 준수하고 표준도메인 기준으로 표준용어를 활용 및 생성해야 함
  - 표준도메인의 추가 생성을 최소화하며 도메인 추가 생성 필요시 발주기관의 담당자와 협의하여 진행하여야 함
- 데이터베이스 명명규칙 등 DB표준 사항을 개발표준에 정의한 후 프로젝트 전 공정에 이를 준용하여 시행함
- 시스템 구현 과정에서 표준 변경이 요구될 경우 주관기관과 협의하여 개발 표준 정의서 개정 작업을 실시하여야 함

### DAR-002 데이터 표준 관리

- 데이터 표준관리 방안 제시
  - 시스템 구축기간 동안 데이터 표준 관리를 위한 방안(변경이력 포함)을 제시하고 표준 사전과 데이터 항목의 일치여부를 주기적으로 점검하여야 함

### DAR-003 데이터 구조 설계

- 데이터 구조 설계 기준 제시
  - 데이터 구조 설계(모델링) 기준을 제시하고 이를 준수하여 데이터 구조를 설계, 구현하여야 함
- 데이터 주제영역 정의 및 개념·논리·물리 모델 설계
  - 데이터 활용, 업무요건 변화, 시스템 변경 등으로 인한 DB의 구조적 변화가 최소화될 수 있도록 유연한 구조로 설계하여야 함
  - 데이터 분류체계, 명명 규칙, DB Object 사용기준이 반영되어야 함
  - 주제영역, 개념 데이터 모델, 논리 데이터 모델, 물리 데이터 모델의 설계 산출물을 사전에 검토할 수 있도록 제출하여야 함
  - 업무규칙(BR) 처리를 위한 데이터 주제영역, 개념 데이터 모델, 논리 데이터 모델, 물리 데이터 모델이 설계되어야 함
  - 데이터 설계 표준(데이터 분류체계, 명명 규칙, DB Object 사용기준 등)을 정의하고 적용하여야 함
- 데이터 모델링 관리 정책 수립
  - 사용자 요구사항 반영에 유연하게 신속 대응할 수 있도록 표준화된 데이터 모델링 정책 수립
  - 데이터의 명확성을 확보하여 신뢰성을 제고하고, 개발 생산성을 확보할 수 있는 관리체계 구축
  - 지속적이고 주기적인 품질관리 활동에 대한 기준을 수립
  - 데이터 중복을 최소화하고 직관적인 데이터 처리 프로세스 정의

### DAR-004 데이터 구조 검증

- 데이터 모델 검증
  - 설계된 데이터 모델은 설계자·개발자·발주기관·전문가 등이 참여하여 검증하여야 함
  - 주제영역 도출, 개념모델, 논리모델, 물리모델 도출 시점을 전후로 검증과 교육을 수행해야 함
  - 각 단계별 데이터 모델 검증 시 기준을 정의하고 실시하여야 함
  - 논리데이터 모델 검증 기준: 요구사항 대비 논리 모델의 완전성, 논리데이터 모델의 비즈니스 요구사항 누락 여부, 정규화 충족 여부
  - 물리데이터 모델 검증 기준: 중복 테이블 여부, 중복 컬럼 여부, 반정규화된 중복 데이터 정합성 유지 방안 여부

### DAR-005 데이터 구조 관리

- 데이터 구조 관리 방안 제시
  - 데이터 구조를 설계부터 구축, 운영 단계까지 지속적으로 관리할 수 있는 방안을 제시하여야 함
  - 시스템 구축 기간 동안 DB의 형상과 물리 데이터 모델의 형상 일치 여부를 주기적으로 점검하고 보고하여야 함
  - 데이터베이스 모델 적용현황(모델과 DB간 갭분석 등) 최종 점검 수행 및 제출
- 데이터 구조 변경이력에 대한 관리방안을 제시하고 적용하여야 함
- 데이터 품질관리 정책 수립
  - 시스템 구축 후 시스템 상시 운영 시 데이터 품질 향상을 위한 데이터 품질 관리 모니터링 구축 방안 요건 도출
  - 데이터 품질지표(DQI)를 통한 품질 평가관리, 데이터 표준/모델 개선 등 품질 향상 방안 수립

### DAR-006 데이터 값 검증 방안

- 데이터 값 검증 방안 제시
  - 시스템 구축 후 입력되는 데이터들에 대한 값 검증 및 오류 데이터 입력 방지 방안을 제시하고 적용하여야 함
  - 목표시스템(DB)의 구축·운영 근거(법령, 규정, 규칙, 매뉴얼 등)에 맞는 업무규칙(BR)를 정의하여야 함
- 업무규칙(BR) 적용 지원
  - 시스템의 업무규칙(BR)은 발주기관의 데이터품질관리시스템에 등록 및 현행화 되도록 지원하여야 함
  - 공공데이터 품질관리 수준진단 평가 기준으로 최소 8개 이상 추가발굴 등록하여야 함
- 데이터 값 진단 계획 수립
  - 데이터(연계데이터 포함) 값 진단 수행 일정을 사업 계획에 명시하고 수행하여야 함
- 데이터 값 진단 수행 및 검증
  - 데이터 값 진단 범위(전체 또는 일부)를 발주기관과 협의하여야 함
  - 범정부 또는 발주기관의 표준을 준수하여 진단기준을 제시 및 수행하여야 함
  - 진단 결과에 따라 오류보정 및 개선방안을 제시하여야 함
- 이행 데이터 업무규칙 수립
  - 구축 사업 관련 법률, 지침, 규정 등을 기반으로 한 업무규칙을 수립
  - AS-IS 시스템의 데이터에 대한 데이터 정합성 검증을 위한 업무규칙 도출(20개 이상)
  - 사업규모에 따라 수행여부 및 개수 변경 협의 조정
- 데이터 값 검증 방안 요구사항은 발주기관과 협의 후 필요시 수행

### DAR-007 데이터 관리체계 수립

- 운영단계까지 지속적으로 적용가능한 데이터 관리체계 정의
  - 데이터 표준, 구조, 값 등 데이터 핵심 요소의 지속적인 관리를 위한 조직과 역할을 정의하여야 함
  - DB표준(단어·용어·도메인·코드)의 추가, 변경, 삭제 절차를 수립하여야 함
  - 데이터 구조(논리·물리)와 관련된 추가, 변경, 삭제 절차를 수립하여야 함
  - 관리체계에는 표준 준수율, 구조 현행화율, 값 검증 오류율 등 명확한 관리기준을 제시하여야 함
- 연계데이터 관리방안 제시
  - 제공기관 및 활용기관 간 연계데이터의 정합성이 유지되도록 방안을 제시하고 구축하여야 함
  - 연계데이터 목록을 정의하고 관리 방안을 제시하여야 함
  - 연계 정보(송·수신 구분, 정보명, 주기), 연계 항목(항목명, 설명, 데이터 타입, 길이), 항목 출처(DB, 테이블, 컬럼명), 제공기관, 활용기관 등을 포함하여야 함
  - 연계데이터를 제공 및 활용하는 기관 상호 간의 데이터 품질 확보를 위해 연계표준이나 기준 등을 협의하고, 정기적인 연계데이터 정합성 검증을 수행하여야 함

### DAR-008 데이터 개방 및 메타데이터 관리체계

- 메타데이터 현행화
  - 목표시스템의 메타데이터 표준 관리 항목이 발주기관의 메타데이터 관리시스템과 중앙메타시스템에 등록 및 현행화되도록 지원하여야 함
- 데이터 개방(필요시)
  - 목표시스템의 데이터가 공공데이터 포털 등을 통해 파일 또는 API 등의 형태로 개방될 수 있도록 지원하여야 함
- 데이터 개방 및 메타데이터 관리체계 수립 요구사항은 발주기관과 협의 후 필요시 수행

### DAR-009 데이터베이스 모델링 설계

- 데이터 모델링 설계 방향성
  - DB 구조의 설계는 관련 업무 처리 절차를 반영하여 구조화하고 향후 업무 변동에 따른 확장성을 충분히 고려해야 함
  - 데이터 관리 지침을 수용할 수 있도록 DB설계가 되어야 함
  - 데이터의 정합성을 유지하면서 시스템의 성능을 저하시키지 않도록 DB 설계가 되어야 함
  - 발주기관의 데이터 품질 가이드와 행정정보 데이터베이스 표준화 지침을 준수하여 DB를 설계하여야 함
  - DB설계는 모델링 도구를 활용하여 작성하고 공유할 수 있어야 함
- DB세부항목 정합성 심층 분석 및 정제
  - 정합성 규칙 작성, 데이터 분석·정제·관리 개선 방안 도출
- 데이터 모델링
  - 현행 업무시스템을 분석하여 데이터 관련 요건 및 최종 데이터생성 시기 등을 분석하여 데이터베이스 설계 표준 및 가이드에 따라서 논리적, 물리적 데이터 모델링을 수행
  - 표준 및 가이드는 발주기관의 정책을 준용함
  - 업무특성 및 연관성을 고려하여 중복이 발생하지 않고, 공유·활용 및 업무요건변경, 프로그램 수정요청에 따른 구조적 변화가 최소화될 수 있도록 유연한 통합 DB설계(논리/물리모델)
  - 시스템의 기준정보를 정의하고, 주체와 행위를 명확하게 구분하여 응용시스템 구조 변경과 업무 변화까지 고려하여 설계
  - 대량 업무정보 조회와 탐색 등에도 데이터베이스의 성능이 확보될 수 있도록 설계
  - 데이터 표준화규칙에 기반한 명명규칙에 따라 논리모델 및 물리모델의 데이터 요소에 반영
  - 개인정보가 노출되지 않도록 보안을 고려
- 데이터 모델링 실행 방안 제시
  - 데이터 모델링에 대한 방법론, 투입 인력, 기간, 상세 수행 내역 등 종합적으로 검토하여 방안 제시
  - 응용시스템 설계 파트와 데이터베이스 설계 파트 상호간에 긴밀히 협조
  - 표준 데이터 아키텍처를 정의하고 실제 데이터베이스 설계 및 구축을 위해 DB 모델링 도구를 통한 설계 실시
- 데이터 구조 설계 원칙 및 가이드 제시
  - 데이터 구조 설계(모델링) 원칙 및 가이드를 제시하고 이를 준수하여 데이터 구조를 설계, 구현하여야 함
  - 일관성, 데이터의 종속성, 무결성, DB 성능 등이 고려되어야 함
- 데이터 주제영역 정의 및 논리·물리 모델 설계
  - 데이터 공유 및 활용, 업무요건 변화, 시스템 변경으로 인한 DB의 구조적 변화가 최소화될 수 있도록 유연한 구조로 설계하여야 함
  - 데이터 분류체계, 명명 규칙, DB Object 사용기준이 반영되어야 함
  - 주제영역, 개념 데이터 모델, 논리 데이터 모델, 물리 데이터 모델의 설계 산출물을 사전에 검토할 수 있도록 제출하여야 함
- 데이터베이스의 정규화 수행
  - 발주기관 데이터베이스에 적용 가능한 정규화 유형을 정의하고, 만약 정규화가 되지 못할 경우 정확한 사유를 보고

### DAR-010 데이터 표준화

- 발주기관 ｢데이터 표준화 지침｣ 및 표준화 프로세스 준수
- 발주기관 ｢데이터 품질관리 지침｣ 및 품질관리 프로세스 준수
- 발주기관 데이터 표준 정책에 기반하여 기준 정보 관리
  - 코드관리체계, 표준화(단어, 용어, 도메인 등) 방안 등 수립
  - DB 구축 또는 구조 변경 시 메타데이터시스템 정책 적용

  - 매핑정의서의 매핑규칙에 맞게 이행되었는지 검증하여야 함

  - 데이터 전환 시험을 수행한 후 데이터 전환 시험결과를 분석하여, 오류 데이터 결함 발견 시 오류의 원인이 제거될 수 있도록 전환 시험을 지속적으로 실시하고 전환 시험결과에 대한 이력을 지속적으로 관리하여야 함
  - 발생 가능한 비상 상황별로 시나리오를 작성하여 데이터 전환 업무를 안정적(소요시간, 데이터 정합성 등)으로 수행하여야 함
- 테스트 관리 및 수행 지원 도구 활용
  - 데이터 전환 시 적합한 테스트 관리 및 수행 지원 도구 활용방안 제시
- 데이터 전환 시험의 대상, 범위(1~n차), 수행절차, 조직, 일정, 시험환경, 이관 소요시간, 데이터 정합성에 대한 검증기준을 구체적으로 수립하고 발주기관과 합의 후 테스트를 수행하여야 함
- 실 전환환경 구성 후 전체 데이터를 대상으로 이행 시 성능 및 데이터 정합성 검증
  - 데이터 전환 시나리오 및 데이터 검증방안을 수립하여 데이터 전환 계획에 반영하고 본 데이터 이행 수행
  - 현행 데이터 추출, 전송, 적재, 정제, 변환 등 데이터 가공 단계별 데이터 검증을 원칙으로 하되, 단계별로 발주기관과 협의 후 다음 단계의 작업 수행
  - 데이터 적재, 코드, 허용 값, 참조 무결성 검증 수행
- 전환 데이터를 사용하여 외부기관 연계, 응용시스템 등에 대한 통합테스트를 실시하여야 함
- 고려사항
  - 데이터 전환 차수별 목표 및 차세대 최종 오픈을 위한 기준을 데이터 전환 계획서에 명확히 제시
- 데이터 전환 관련 제반 테스트 실시 요구사항은 발주기관과 협의 후 필요시 수행

### DAR-018 데이터 정비(클렌징) 수행

- 품질진단 수행
  - 데이터 이행작업과 연동하여 현행 데이터에 대한 효과적인 데이터 품질점검 방안 제시
  - 효과적인 데이터 품질진단, 지속적인 품질관리를 위한 방안 제시
  - 업무분석 결과(AP팀 수행) 도출된 업무규칙을 적용한 검증 프로그램을 통해 현행 및 목표 데이터 구축 위한 품질진단에 활용
- 데이터 품질 측정, 분석, 데이터 품질 개선 계획 수립
  - 데이터 품질 지표, 핵심정보 항목 등 컨설팅 및 품질점검 수행
  - 기술적 분석의 데이터 프로파일링 수행(컬럼분석, 참조무결성 분석, 코드분석, 패턴분석, 날짜 데이터 분석 등)
- 데이터 이행 전 데이터 정비(클렌징) 작업 수행
  - 데이터 속성(컬럼, 참조무결성, 코드, 패턴 등)을 고려한 데이터 정비(클렌징) 작업 수행
  - 주요 데이터 사전정비 작업 수행
  - 데이터분석, 사전정비용 화면 설계 및 구현, 정비데이터 보완 등 수행
- 데이터 분리보관 기준 수립
  - 데이터 제공 대상 여부, 이용주기, 활용빈도, 중요도 등을 분석하여 데이터 분리 보관 기준 수립
  - 분리보관 기준은 데이터관리 생명주기 관리 기능의 기준정보로 제공
- 데이터 정비(클렌징) 수행 요구사항은 발주기관과 협의 후 필요시 수행

### DAR-019 개인정보보호법 등 관련 지침에 따른 데이터 보안 적용

- 개인정보보호법에 의해 보호되어야 하는 개인정보는 데이터 보안을 적용
  - 주민번호 및 생체정보, 비밀번호 등 DB 저장 시 암호화
  - 스캔파일, 신청서식, 구비서류 등 개인정보가 포함된 파일도 암호화 대상 포함
  - 개인정보 관련 DB데이터 암/복호화 권한 관리
  - 암호화 키 관리 체계 마련
- 테스트 데이터 변환
  - 개발(테스트) 서버에 테스트 데이터 제공 시 발주기관은 개인정보 보호를 위해 운영시스템의 암호화된 개인정보를 복호화하여 가명 처리 후 개발계 암호화키로 암호화하여 제공
  - 수행사는 개발 및 테스트 기간 동안 테스트 데이터 변환에 필요한 가명 처리 솔루션과 그에 필요한 기술지원을 발주기관에 제공해야 함
  - 변환 시 데이터 간 엔터티 relation 유지
  - 개발(테스트)서버와 운영서버의 암복호화 키는 발주기관에서 별도 관리

### DAR-020 데이터 무결성 확보 DB 암호화 수행

- 개인정보암호화 선정기준
  - 관련 법·규정을 참조하여 발주기관과 협의
- 개인정보암호화 대상 목록
- 암호화 수행 일정
- DB암호화 솔루션을 통한 데이터에 대한 개인정보 암호화 실행

### DAR-021 공공데이터 법령 및 지침 준수

- 신규 정보시스템 구축 또는 고도화 시, 제공 대상이 아닌 정보(개인정보 등)는 별도 테이블로 분리하여 설계할 것을 권고
  - 향후 공공데이터 개방 관리는 DB의 테이블 단위 또는 연관 테이블의 집합 형태로 개방 고려됨을 감안하여 설계
  - 데이터 요구사항에 명시된 과업은 공공데이터 관련 법령 및 지침 등을 준수하여 추진 필요
- 공공데이터 관련 법령 및 지침 준수
  - 「공공데이터의 제공 및 이용 활성화에 관한 법률」 및 동법 시행령, 시행규칙
  - 「공공데이터 관리지침」
  - 「공공기관의 데이터베이스 표준화 지침」
  - 「공공기관의 공공데이터 활용 서비스 개발‧제공 가이드라인」
  - 「공공데이터 품질관리 매뉴얼」
- 프로젝트 진행 중에 발생하는 관련법령 개정사항 준수
