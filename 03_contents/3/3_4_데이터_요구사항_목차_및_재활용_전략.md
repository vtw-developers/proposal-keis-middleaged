# 3.4 데이터 요구사항 목차 및 일경험 제안서 재활용 전략

## 1. 검토 결론

일경험 제안서의 데이터 요구사항 장표는 **목차 골격과 장표 전개 방식의 재활용성이 높음**.

다만 현재 사업은 **중장년내일센터 업무시스템의 고용24 행정포털 통합 재구축**이므로, 일경험 제안서의 업무 예시를 그대로 가져오면 부적합함.

따라서 다음 방향으로 재구성함.

- 일경험 제안서의 **데이터 표준화, 모델링, 값 검증, 전환, 클렌징, 품질관리, DB 보안** 구조는 재활용
- 현재 RFP의 **DAR-001~DAR-021 전체 요구사항**을 빠짐없이 반영
- 현재 사업 특화 요소인 **고용24 공통 적용, EDMS 첨부파일 이관, 개인정보/DB 암호화, DW 통계 기반**을 신규 보강
- 데이터 요구사항을 단순 기술 설명이 아니라 **고용24 통합 운영을 위한 데이터 기반 구축 전략**으로 제시
- 기존 3.4.1~3.4.15 단일 나열형 목차를 일경험 원 목차처럼 **대분류 → 세부 장표** 구조로 한 뎁스 더 세분화

---

## 2. 3.4 데이터 요구사항 작성 방향

### 장표 메시지 방향

> 중장년내일센터 업무데이터의 표준화, 정제, 이관, 검증, 보안, 성능 최적화를 통해 고용24 행정포털 통합 운영에 적합한 고품질 데이터 기반을 구축합니다.

### 핵심 작성 관점

- **표준화**: 단어, 용어, 도메인, 코드, 명명규칙 표준화
- **구조화**: 업무 중심 주제영역, 개념/논리/물리 모델 설계
- **전환성**: AS-IS 데이터 분석, TO-BE 매핑, 이관 리허설, 정합성 검증
- **품질성**: BR 기반 값 검증, 오류 데이터 보정, 품질지표 관리
- **보안성**: 개인정보 데이터 보호, DB 암호화, 테스트 데이터 가명처리
- **통합성**: 고용24 공통, EDMS, 연계 데이터, DW 통계 기반 반영
- **운영성**: 운영단계까지 이어지는 데이터 구조/표준/품질 관리체계 수립

### 원 목차 적용 판단

일경험 제안서 원 목차는 **데이터 표준 → 데이터 설계 → 데이터 검증 → 데이터 이행 → 데이터 품질 → DB 보안**의 흐름으로 구성되어 있어 현 사업에도 기본 골격으로 활용 가능함.

다만 현 사업은 다음 항목이 일경험 제안서보다 중요하므로 목차를 보강해야 함.

- **EDMS 첨부파일 이관**
- **고용24 공통 적용 데이터 전환**
- **개인정보/DB 암호화 강화**
- **의사결정용 DW 통계 데이터 기반**
- **중장년내일센터 원천시스템 전체 데이터 이관**

따라서 현 사업 3.4 목차는 일경험의 6.1~6.7 구조를 유지하되, 단순 3.4.1~3.4.15 나열이 아니라 **3.4.1~3.4.7 대분류 아래 세부 장표를 배치하는 구조**가 적합함.

## 6. 목차별 장표 구성 방향

### 3.4.1.1 데이터 요구사항 대응 개요

**장표 목적**
- 데이터 요구사항 전체 대응 범위를 한 장에서 설명
- DAR-001~021이 표준, 구조, 품질, 전환, 보안, 성능, 공공데이터로 빠짐없이 대응됨을 제시

**중앙 도식 추천**
- `표준화 → 구조설계 → 품질검증 → 전환이행 → 보안/암호화 → 운영관리` 흐름도
- 하단에 `고용24 통합 운영 데이터 기반 구축` 메시지 배치

**재활용 전략**
- 일경험 제안서의 데이터 관리 개요 장표 재활용
- 청년 일경험 용어를 중장년내일센터 업무데이터로 치환

---

### 3.4.2.1 데이터 표준 수립 및 관리체계

**장표 목적**
- 단어, 용어, 도메인, 코드 표준을 수립하고 상위표준 준수 방안을 제시

**주요 내용**
- 데이터 표준사전 제정
- 범정부 표준 및 발주기관 표준 준수
- 표준 변경 요청·검토·승인·반영 절차
- 표준 준수율 점검

**재활용 전략**
- 일경험 제안서의 데이터 표준화 장표 구조 재활용
- 예시 데이터는 고객/참여자, 상담 이력, 교육 프로그램, 기업서비스, 지원금/인센티브, 실적/통계, 공통코드로 교체

### 3.4.5.5 EDMS 첨부파일 이관 및 파일 데이터 관리

**장표 목적**

**주요 내용**
- 첨부파일 원천 데이터 분석
- 업무데이터와 첨부파일 매핑
- EDMS 이관 대상 파일 정의
- 파일 메타데이터 검증
- 파일 암호화 및 접근권한 고려
- 첨부파일 관련 서비스 로직 변경 영향도 반영

**중앙 도식 추천**
- `AS-IS 업무DB/파일저장소 → 파일 메타 매핑 → EDMS 이관 → 업무서비스 연계 검증` 흐름도

**재활용 전략**
- 신규 작성 필요
- 데이터 전환 절차와 검증 방식은 일경험 6.5 구조 활용

## 10. 최종 제안 방향

3.4 데이터 요구사항은 일경험 제안서의 데이터 요구사항 목차를 기본 골격으로 활용하되, 기존 15개 장표를 그대로 나열하지 않고 **대분류 중심의 계층형 목차**로 재구성한다.

최종 제안 방향은 다음과 같음.

- **일경험 원 목차 재활용**: 데이터 관리 개요, 표준, 설계, 검증, 이행, 품질, 보안 흐름 유지
- **현 사업 특화 보강**: EDMS, 고용24 공통, DW 통계, 개인정보/DB 암호화 반영
- **평가 대응 강화**: 데이터 전환 계획, 검증 방법, 에러 데이터 처리 방법을 3.4.5 데이터 이행 영역에 집중 배치
- **장표 구성 명확화**: 각 대분류 아래 세부 장표를 배치하여 제안서 목차의 깊이와 전문성을 확보
- **업무 예시 전면 치환**: 일경험 사업 예시는 모두 제거하고 중장년내일센터 업무데이터 기준으로 재작성

따라서 3.4 데이터 요구사항은 다음 메시지로 정리할 수 있음.

> 일경험 제안서의 데이터 관리 프레임을 재활용하되, 중장년내일센터의 고용24 통합, EDMS 첨부파일 이관, 고용24 공통 적용, 개인정보/DB 보안, DW 통계 기반을 반영한 데이터 전환·품질관리 중심의 실행형 목차로 재구성합니다.
